# Fixtures: WorldEd's output for the building experiments

Everything here was made by **running WorldEd** (`PZWorldEd_cli`) on a project and keeping what it
wrote. It is the reference the Python building rules (`knoxbuild/buildtiles.py`, `buildroofs.py`)
are checked against. Nothing here is generated by the code under test.

```
bx/<case>/            31 hand-made buildings, one feature each (a room, a door, a window, stairs, a roof ...)
    buildings/<case>.tbx    the BuildingEd file that was compiled
    <case>.pzw              the WorldEd project (names the lot: x=40 y=40 of the first 300 x 300 cell)
    lots/82_0.lotheader, world_82_0.lotpack     WorldEd's output for the cell that holds the building
exp/house/            one real KnoxMap house (4 levels, 148 rooms, 1,000+ furniture pieces)
    buildings/house_0000.tbx, house.pzw, lots/83_2.*      building at world tile (269, 592)
real/real1/           a real KnoxMap map: 113 buildings + fences and lights
    buildings/*.tbx, real1.pzw, lots/*  (27 files, 9 cells)  every lot is listed in the .pzw
```

Coordinates: the lot files are named by 256-tile cells counted from world tile x = -21000
(the world origin 70,0 in 300-tile cells), so world tile `tx` is in cell `(21000 + tx) // 256`,
local x `(21000 + tx) % 256`. y is not offset. Level z of a building is level `lot level + z`.

## Run the comparisons

From this folder, with a KnoxMap checkout (it supplies `knoxbuild`, `tools`, `knoxpaths`):

```
set KNOXMAP_DIR=C:\KnoxMap          (PowerShell: $env:KNOXMAP_DIR = "C:\KnoxMap")
python bxcheck.py room6x5 door window stairsW roofsA roofsE flat      # hand-made cases, square by square
python housecheck.py exp/house 269 592 house_0000                     # the one real house, per level
python allcheck.py real1 --worst 8                                    # all 113 real buildings
python allcheck.py real1 --worst 4 --show                             # with example squares
python roofdump.py roofsA 0 1 2                                       # roof tiles by BuildingEd name
python bxshow.py roof 38 38 10 9                                      # any case as a letter grid + legend
```

Original fixture baseline: every `bx` case identical except for a few background trees in the margin of the
roof sets; the house identical on every building square of all four levels (level 0 shows 42
squares of terrain around the building, not part of it); `real1` 98.5% of 86,791 squares identical,
12 buildings perfect.

## What is not here

- The bitmaps and `.tmx` terrain of these projects (the building checks do not need them).
- `exp/road`, `exp/water`, `exp/base` (ground and blend checks). Regenerate with
  `experiments/exp.py` in the repo (needs WorldEd installed).
- To remake `bx/*` or `real1` from scratch: `bx.py <case>` and `mkmap.py real1 450`
  (`experiments/` in the repo; both need the mapping tools and, for `mkmap.py`, KnoxMap's
  `cache/overpass_tiles`). A remade `real1` will differ if KnoxMap's building generator changed.


## Additional building rules validation (2026-10-08)

`extra/` contains six new black-box WorldEd CLI captures: custom horizontal and
vertical walls, legacy unusual windows, and three overlap cases. Each includes
the TBX inputs, project, output cell 82_0, and WorldEd log. Generated predictions
are not used as references. WorldEd was run with one worker.

From this folder in PowerShell:

```powershell
$env:KNOXMAP_DIR = "C:\KnoxMap"
$env:PYTHONPATH = $env:KNOXMAP_DIR
& C:\KnoxMap\.venv\Scripts\python.exe -B composecheck.py real/real1 --show
& C:\KnoxMap\.venv\Scripts\python.exe -B -W ignore::ResourceWarning -m unittest discover -s C:\KnoxMap\tests -p test_buildtiles.py
& C:\KnoxMap\.venv\Scripts\python.exe -B -W ignore::ResourceWarning -m unittest discover -s C:\KnoxMap\tests -p test_buildroofs.py
& C:\KnoxMap\.venv\Scripts\python.exe -B -W ignore::ResourceWarning -m unittest discover -s C:\KnoxMap\tests -p test_buildfixtures.py
```

The 40 focused tests cover all 31 existing handmade buildings, the four-level
house, six fresh fixtures, selected real-building regressions, and the new rules.
All pass. Missing local WorldEd fixtures cause their optional tests to skip.

The original independent-building comparison now reports 86,261/86,789 squares
(99.39%), with 45 buildings exact. It includes neighbour-lot tiles as mismatches.
`composecheck.py` places all lots in project order, including utility lots, and
checks unique squares, with a one-square margin around each building. It reports
87,483/88,468 exact and all 357 shared tile squares exact. The wider denominator
is intentional. The 985 remaining differences stay visible; they include paving,
curbs, street decoration and outdoor furniture. They have not been independently
separated from the terrain generator, so this is not a 100% map-match claim.
The checker returns exit code 1 whenever any mismatch remains.

`compose_lots` is the Python building-composition interface for prepared grids.
The existing `level_tiles` flat-stack interface remains available. Rust file
writing is unchanged; building compilation has not been ported into Rust.

Project bitmap/TMX references retain the original machine's absolute paths,
as in the earlier fixtures. Comparing captured output needs only TBX and lot
files; regenerating needs those source assets and WorldEd installed.
